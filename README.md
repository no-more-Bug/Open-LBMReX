# Open-LBMReX

[中文说明](README.zh-CN.md)

Open-LBMReX is a research lattice Boltzmann codebase built on [AMReX](https://github.com/AMReX-Codes/amrex). It provides D2Q9 and D3Q27 case compositions, CPU/MPI and NVIDIA CUDA build routes, cell-centered block-structured AMR, and tests and examples for flow, boundaries and force measurement. The CMake project, C++ interfaces and executable names retain the name **LBMReX**.

**Pre-release:** the first version is planned as `v0.1.0`. The standalone snapshot and its new AMReX installation packages still require build/run validation. Dynamic AMR is experimental. Read the [validation scope](docs/validation.md) and [known limitations](docs/known-limitations.md) before interpreting a successful run as scientific acceptance.

## Project background and release status

This is a personal hobby project and an exercise in AI-assisted coding. It is shared for learning and experimentation, with no guarantee of correctness or continued maintenance. Please independently validate the implementation and results before relying on them for research or engineering work.

LBMReX is developed internally in a private repository. This repository holds curated source-release snapshots of that codebase. Release snapshots omit personal information from the development process and internal development history, while retaining required attribution, licence notices and known limitations. The internal development version is still evolving, so a release snapshot may lag behind it. Further fixes and additions may follow, but there is no committed update schedule.

## Start here

1. [Build AMReX and LBMReX](docs/building.md). The pinned AMReX dependency is installed separately and consumed with `find_package(AMReX)`.
2. Run a [uniform-flow example](showcases/uniform_flow/README.md), then choose a case below.
3. Use the [formal tests](tests/README.md) for engineering checks and [numerical tests](tests/numerical/README.md) for explicit scientific comparisons.

After installing the required AMReX package, this is the CPU example route from the repository root:

```bash
cmake -S . -B build/cpu \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=mpicc -DCMAKE_CXX_COMPILER=mpicxx \
  -DAMReX_ROOT=/absolute/path/to/patched-amrex-install \
  -DLBM_ENABLE_CUDA=OFF -DBUILD_TESTING=OFF -DLBM_BUILD_SHOWCASES=ON
cmake --build build/cpu --parallel 4 --target lbm_uniform_flow
OMP_NUM_THREADS=1 ./build/cpu/lbm_uniform_flow \
  showcases/uniform_flow/inputs/inputs.d2q9_guo_velocity_io
```

The input writes to its showcase-owned `outputs/` and `log/` directories. This short example checks execution and simple observables; it is not a long-time benchmark.

## Examples and testing

The five current showcases are **single-level grid examples**. Their setups or instructions may lag behind ongoing development. All current multilevel-grid cases are maintained in the corresponding [tests](tests/README.md), with the AMR case entry points in [numerical tests](tests/numerical/README.md). Multilevel showcases may be added later, but there is no committed completion date.

| Example | Purpose |
| --- | --- |
| [Uniform flow](showcases/uniform_flow/README.md) | Inlet/outlet schemes, uniform-state preservation and mass checks. |
| [Taylor–Green vortex](showcases/taylor_green_vortex/README.md) | Periodic decay and analytical convergence. |
| [Poiseuille flow](showcases/poiseuille_flow/README.md) | Velocity/pressure-driven channel flow and wall placement. |
| [Lid-driven cavity](showcases/lid_driven_cavity/README.md) | Moving-wall flow and Ghia centerline comparisons. |
| [Channel cylinder](showcases/channel_cylinder/README.md) | Cylinder boundaries, drag/lift and DFG references. |

`src/` contains reusable implementation. Each `showcases/<case>/` owns its composition, inputs, observations and post-processing. `tests/` has separate test-owned compositions and references. Descriptor and dynamics selection lives in C++; inputs expose the controls supported by that case, rather than a universal runtime case registry.

The numerical suite includes static AMR uniform flow, TGV, shear, double shear layer, cavity and cylinder comparisons, plus experimental dynamic-grid cases. D3Q27 compilation and quasi-two-dimensional examples do not establish general three-dimensional scientific validation.

## Dependency and distribution

The official AMReX submodule is pinned to `4ceb814db7d79c5858b13dab153fb04ecc3b129d`. A [small projected-tag deduplication patch](patches/amrex/README.md) is applied to a separate preparation copy; the submodule stays clean. Both D2Q9 and D3Q27 use a **3D, double-precision AMReX package with EB support**.

Git clone with submodule initialization is the main distribution route. An ordinary source archive can use a compatible external AMReX installation; strict numerical runners also require its corresponding public commit identity. Source archives do not bundle AMReX. See [archive use](docs/building.md#ordinary-source-archives).

## Known issues and possible future work

**Parallel validation scope:** CPU-side MPI parallel execution has been tested during development. Due to limited computing resources, GPU-side multi-device parallel testing has only covered NVIDIA MIG slice configurations. Parallel execution across multiple full physical GPUs has not been validated, and successful execution or passing tests on such configurations is not guaranteed. These development results do not replace the independent validation still required for this release snapshot and its new AMReX packages.

Current issues that may be addressed in later snapshots include:

- Dynamic AMR grid granularity and fine-grid coverage/cost tradeoffs still need improvement.
- Some Re100 cylinder comparisons fail their scientific criteria or lack sufficient evidence.
- Sawtooth behavior in AMR force histories remains unresolved, with no established root cause.
- GPU long-run evidence is incomplete: some runs were cancelled, timed out or deferred.

See [known limitations](docs/known-limitations.md) for the full scope. These are open issues, not promises of a particular fix or release date. Short tests and successful program exits do not establish full scientific validation.

## Selected LBM literature

The following works are important references for studying grid refinement and non-uniform-grid LBM:

- [Rohde et al. (2006)](https://doi.org/10.1002/fld.1140): mass-conservative local grid refinement for lattice-Boltzmann schemes.
- [Chen et al. (2006)](https://doi.org/10.1016/j.physa.2005.09.036): grid refinement based on a volumetric formulation.
- [Coreixas and Latt (2025)](https://doi.org/10.1016/j.cpc.2025.109833): GPU-based compressible LBM on non-uniform grids using standard C++ parallelism; [open preprint](https://arxiv.org/abs/2504.04465).
- [Schukmann et al. (2025)](https://doi.org/10.3390/fluids10020031): spurious aeroacoustic emissions on non-uniform grids.

Full bibliographic details and benchmark references are in [scientific references](docs/references.md).
