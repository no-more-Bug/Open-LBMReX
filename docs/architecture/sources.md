# Architecture overview and source map

The [interactive architecture diagram](lbmrex-architecture.html) was automatically generated by AI using [Archify](https://github.com/tt-a1i/archify). Download the HTML and open it in a browser to use its interactive controls. The editable diagram definition is [candidate.json](candidate.json).

This is an overview of execution and ownership, not a complete class diagram or a scientific validation report. Nodes group cooperating code; arrows show calls or dependencies rather than one universal execution sequence. The map may contain omissions or mistakes. Use the source and the [known limitations](../known-limitations.md) as the authority.

## Source entry points

Paths below are relative to the released repository root. These references document the inspected implementation without publishing internal repository history or private filesystem paths.

| Diagram node | Responsibilities and source entry points |
| --- | --- |
| Single-level showcases | Case inputs and C++ composition select the descriptor and dynamics, then prepare and run. See the [uniform-flow entry](../../showcases/uniform_flow/src/main.cpp) and [showcase registration](../../CMakeLists.txt). All five current showcases use the single-level path. |
| AMR test compositions | Test-owned geometry, physical controls, sampling and acceptance. See the [double-shear entry](../../tests/numerical/amr_double_shear_layer/src/main.cpp) and [test registration](../../tests/CMakeLists.txt). [AMR performance compositions](../../tests/performance/src/AmrPerformanceCases.H) reuse numerical cases without their scientific sampling/acceptance policy. |
| Single-level runtime | [Preparation](../../src/runtime/SingleLevelPreparation.H) produces an owned token; [the run implementation](../../src/runtime/SingleLevelRun.HH) executes collision, boundary preparation, streaming, reconstruction and configured observation callbacks. |
| LbmAmrSimulation | Owns level fields, hierarchy and time. See [its interface](../../src/lbm/amr/LbmAmrSimulation.H), [evolution implementation](../../src/lbm/amr/LbmAmrSimulation.HH) and [prepared evolution](../../src/runtime/LbmAmrPreparation.H). |
| LBM building blocks | [LatticeField](../../src/lbm/fields/LatticeField.H) wraps population storage; [CollisionOperator](../../src/lbm/operators/level/CollisionOperator.H) and [PullStreamingOperator](../../src/lbm/operators/level/PullStreamingOperator.H) perform level updates. [BoundarySystem](../../src/lbm/boundary/core/BoundarySystem.H) and [AmrBoundarySystem](../../src/lbm/amr/AmrBoundarySystem.H) organize domain/internal-boundary execution. The runtime owners retain the fields; this node is not another global state owner. |
| AMR hierarchy services | [CoarseFineCoupling](../../src/lbm/amr/CoarseFineCoupling.H), [refinement tagging](../../src/lbm/amr/RefinementTagging.H) and [population remap](../../src/lbm/amr/PopulationRemap.H) support the hierarchy. [LbmAmrSimulation](../../src/lbm/amr/LbmAmrSimulation.HH) schedules subcycling and conditional synchronized regridding, collects interval forces before regridding, and rebuilds affected coupling/boundary state. |
| Case-owned observation | The [single-level runtime](../../src/runtime/SingleLevelRun.HH) invokes case callbacks. The [AMR case entry](../../tests/numerical/amr_double_shear_layer/src/main.cpp) supplies observers and output ownership. Observers borrow published state rather than owning another solver. |
| Numerical artifacts | [AmrSampleOutput](../../tests/numerical/common/AmrSampleOutput.HH) writes layout/sample CSVs and invokes native plotfile writers. [Showcase output code](../../showcases/uniform_flow/src/uniform_flow/runtime/RunOutput.H) owns case output paths. Files are consumed by case/test post-processing and checkers; the diagram does not imply every observer always writes every format. |
| AMReX installation | [CMake](../../CMakeLists.txt) consumes an external installation through find_package and links AMReX::amrex_3d. [Fields](../../src/lbm/fields/LatticeField.H) and [operators](../../src/lbm/operators/level/CollisionOperator.H) use its mesh, distributed storage and execution facilities. See [building](../building.md) for the pinned source, patch and separate CPU/CUDA packages. |

## Interpretation limits

Dynamic AMR remains experimental. CPU MPI has been tested during development; limited computing resources restricted GPU multi-device tests to MIG slice configurations, so multiple full physical GPUs remain unvalidated. Diagram generation and browser checks do not validate solver behavior or the new release packages.
