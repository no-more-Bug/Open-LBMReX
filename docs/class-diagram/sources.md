# Key classes, functions and source map

Open the [class-diagram navigator](index.html), or go directly to [single-level preparation](single-level.html), [AMR evolution](amr.html), or [fields and operators](fields-operators.html). All three diagrams were automatically generated by AI using [Archify](https://github.com/tt-a1i/archify).

These views select important declarations and relationships rather than listing every class or method. They may contain omissions or mistakes; the source is authoritative. The editable definitions are [single-level.json](single-level.json), [amr.json](amr.json) and [fields-operators.json](fields-operators.json). Source paths below use the released repository layout.

## Reading the notation

- Composition denotes owned subobjects, including ownership through optional or unique_ptr storage. An association labelled “borrows” does not transfer ownership.
- Dependency denotes a selected use, such as passing a field to an operator; it does not imply a retained pointer or virtual dispatch.
- D = Descriptor, P = initialization profile, T = tagging type, C = collision operator. In the fields/operators view, the illustrated Dyn specialization is BGKDynamics<D>.
- Field abbreviates LatticeField<D>; PreparedRun abbreviates PreparedSingleLevelRun<...>; Simulation abbreviates LbmAmrSimulation<D,P,T>; Real is amrex::Real; ForceBatch is boundary::InternalForceBatch; Diagnostics abbreviates the setup-diagnostic vector. These are diagram shorthand, not new source aliases.
- Template arguments, overloads, const/noexcept qualifiers, most constructors and some parameters are omitted for readability. A slash groups existing fields, such as src / dst; it is not a literal C++ identifier.
- Private nested State and LevelFields records are included to explain ownership. They are implementation details, not public construction interfaces.
- Free functions are listed separately below and in diagram cards; they have not been invented as methods of a synthetic class.

## Single-level types

| Types | Source and interpretation |
| --- | --- |
| SingleLevelProgram | [SingleLevelProgram.H](../../src/runtime/SingleLevelProgram.H): parser-free mesh, physics, dynamics, run and case-preparation intent. It is not retained as another runtime state owner. |
| SingleLevelPreparationResult / PreparedSingleLevelRun | [SingleLevelPreparation.H](../../src/runtime/SingleLevelPreparation.H): optional success token, diagnostics and move-only transfer. A fresh token is obtained through successful preparation; existing tokens can be moved. |
| PreparedSingleLevelRun::State | [SingleLevelPreparation.HH](../../src/runtime/SingleLevelPreparation.HH): private nested storage owns the resolved boundaries, dynamics, case RunSession and two population buffers. |
| BoundarySystem<D> | [BoundarySystem.H](../../src/lbm/boundary/core/BoundarySystem.H): resolves/binds domain and internal geometry, then supplies boundary-stage and force operations. Time advancement stays with the runtime. |
| SingleLevelPublishedState<D> | [SingleLevelRunSession.H](../../src/runtime/SingleLevelRunSession.H): a read-only, non-copyable/non-movable, callback-scoped view. MacroField is present only when requested. |

## AMR types

| Types | Source and interpretation |
| --- | --- |
| LbmAmrSimulation / LevelFields | [LbmAmrSimulation.H](../../src/lbm/amr/LbmAmrSimulation.H): the simulation privately inherits amrex::AmrCore, owns the hierarchy, per-level fields, boundaries and coupling. The external base is named in the diagram but its class tree is omitted. |
| PreparedAmrEvolution / LevelEvolution | [PreparedAmrEvolution.H](../../src/lbm/amr/PreparedAmrEvolution.H): immutable run dependencies contain each allowed level's collision operator, local units and time step. They are borrowed by evolve(), not owned by the simulation. |
| CoarseFineCoupling<D> | [CoarseFineCoupling.H](../../src/lbm/amr/CoarseFineCoupling.H): explode/coalesce for one adjacent level pair. Layout changes require reconstruction; borrowed population pointers do not survive an exchange. |
| AmrBoundarySystem<D> | [AmrBoundarySystem.H](../../src/lbm/amr/AmrBoundarySystem.H): owns global boundary identities and per-level domain/internal records; it does not inherit the single-level BoundarySystem. |
| LbmAmrView / LbmAmrLevelView | [LbmAmrSimulation.H](../../src/lbm/amr/LbmAmrSimulation.H): the top view owns a vector of level-view records, but those records borrow fields. Omitting a relationship line does not turn borrowed populations into owned data. |
| Evolution and regridding methods | [LbmAmrSimulation.HH](../../src/lbm/amr/LbmAmrSimulation.HH): subcycling, coarse/fine exchange, synchronized observation and conditional dynamic regridding. Force batches are collected before a regrid can replace their collectors. |
